## Kesimpulan akhir: `index.ino` dan `index.html`

### Peran `index.ino` (ESP32 — sumber kebenaran kontrol)

Firmware ini menjadi **otak lapangan**: membaca sensor, menghitung **tiga skor fuzzy terpisah** (masing-masing 0–1 dengan fungsi keanggotaan trapesium/segitiga lalu agregasi Sugeno ringan), lalu menggerakkan **tiga relay** sesuai ambang `RELAY_FUZZY_THRESHOLD` (0,5).

```15:19:d:\TA\git ta\index.ino
 * - Tiga jalur sensor → tiga relay (masing-masing dengan fuzzy Sugeno ringan):
 *   - Suhu udara (DHT11) → skor fuzzy paranet → relay paranet (ON jika skor ≥ ambang).
 *   - Kelembaban tanah → skor fuzzy kebutuhan air → relay penyiraman air.
 *   - pH tanah → skor fuzzy koreksi pH → relay larutan / koreksi pH.
 * - Skor 0–1: fuzzy_suhu (suhu/paranet), fuzzy_soil (tanah/air), fuzzy_ph — ke MQTT & Supabase.
```

- **Paranet**: dari suhu (hanya jika DHT valid).  
- **Air**: dari persen kelembaban tanah.  
- **pH**: dari pH dalam rentang wajar; relay pH memakai pin `RELAY_PH_PIN`, sementara ke Supabase status itu tetap bisa masuk kolom legacy `relay_dolomit` agar cocok dengan skema tabel lama.

Data dikirim **dua jalur**: **MQTT** (cepat, untuk dashboard live) dan **Supabase REST** (lebih jarang, untuk log). Body Supabase memakai nama kolom **`fuzzy_suhu`**, **`fuzzy_soil`**, **`fuzzy_ph`**, plus **`relay_paranet`**, **`relay_air`**, **`relay_dolomit`** (isi = relay koreksi pH).

### Peran `index.html` (dashboard — tampilan & riwayat)

Halaman ini **tidak mengendalikan relay**; ia **mengamati** data yang sama dengan yang dipublish ESP32: koneksi **WebSocket MQTT** ke broker yang sama, subscribe topik **`pertanian/sensor`**, parse JSON, isi kartu sensor, tiga skor fuzzy, tiga status relay, serta indikator WiFi (dari field `wifi_connected` / `wifi_ip` bila ada).

```4:8:d:\TA\git ta\index.html
  Halaman ini:
  - Terkoneksi ke broker MQTT EMQX via WebSocket (wss).
  - Subscribe topic "pertanian/sensor" yang dikirim ESP32.
  - Menampilkan data sensor, skor fuzzy_suhu / fuzzy_soil / fuzzy_ph, tiga relay (paranet, air, koreksi pH).
  - Memuat riwayat log dari Supabase (REST) — sama dengan data yang di-insert ESP32.
```

Di JavaScript, dashboard **mengikuti kontrak nama terbaru** (`fuzzy_suhu`, `relay_ph`, dll.) tetapi tetap punya **fallback** ke payload lama (`fuzzy_air`, `relay_dolomit`) supaya firmware atau baris database lama tidak membuat tampilan kosong.

### Satu kalimat penutup

**`index.ino`** memutuskan kontrol tiga relay dari tiga skor fuzzy dan mendorong data ke MQTT + Supabase; **`index.html`** hanya **memantau** jalur MQTT yang sama dan **mengingat** pola data di Supabase, dengan kompatibilitas mundur untuk nama field lama — sehingga keduanya membentuk satu sistem: **ESP32 = kontrol + produksi data**, **dashboard = visualisasi real-time + arsip**.
